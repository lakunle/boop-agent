M2 — Voice

Dedicated voice-mode screen for the Boop iOS native client. Continuous-loop hands-free conversation with streaming TTS.

v1 · 2026-05-23 milestone M2 brainstorm approved implementation plan pending 3 weekends

1 Overview #

What M2 ships and why.

M2 adds a dedicated voice-mode screen to the Boop iOS app. The user taps the mic button in the existing dock, a full-screen sheet opens, and they have a hands-free conversation with boop — on-device speech-to-text, streamed assistant reply, streamed text-to-speech back through AirPods. Each turn lands in the currently-active thread as a normal message.

The milestone is intentionally not a chat-composer mic button. The earlier brainstorm picked the dedicated-screen path because hands-free with AirPods is the use case driving the feature, and the orb / state-machine UX is qualitatively different from "type by voice."

What the user can do after M2 ships

  • Tap the dock mic on any active thread → speak naturally → hear the reply.
  • Carry a back-and-forth conversation without touching the phone (continuous loop).
  • Tap the orb mid-reply to skip ahead.
  • Mute mid-session in a noisy environment without exiting.
  • Fall back to text by tapping the keyboard control — the latest partial transcript lands in the composer.
  • Replies are persisted to the active thread; closing voice mode leaves a normal chat scrollback behind.

What M2 is not

  • Not a chat-composer mic button (decided against in the brainstorm).
  • Not interruptible mid-TTS (no barge-in — that's the M2.5 candidate).
  • Not a separate "Voice" thread (turns continue the active thread).
  • Not backgrounded / always-listening (battery + entitlements; explicit non-goal).
  • Not Siri / Shortcuts / Action Button entry (that's M4).

3 Architecture #

Components, data flow, and what changes vs. what's reused from M1.

Inbound (user speaks)

   ↓ partial transcripts // rendered on orb

   ↓
[iPhone] POST /channels/ios/inbound // existing M1 endpoint

   ↓
[server] runTurn(inbound)  // unchanged shape
   ↓
[server] agent system prompt += voice-mode addendum

Outbound (assistant responds)

[server] SDK streaming callback → broadcast("assistant_delta")
   ↓ NEW: voice-mode sidecar subscribes
[server] SentenceBuffer: accumulate tokens, emit on .!?:\n boundaries

[iPhone] orb → idle, re-arm mic (continuous loop)

4 UX & state machine #

The four states, the controls, and the transitions between them.

Visual states

StateOrbSubtitleMic
listeningCalm pulse (Lottie). Tinted by active thread.Live partial transcript fades in.Hot. VAD watching.
thinkingSlower, deliberate motion.Frozen transcript of last user utterance.Cold.
speakingAmplitude-modulated by audio level.Assistant text streams in (1–2 lines).Cold. Tap orb to skip.
pausedStatic + muted glyph."Tap to resume."Cold.
errorDim, static.Error message + retry.Cold.

Controls

  • 🔇 Mute — pause without exiting. Useful in noisy environments / interruptions. Tap again to resume.
  • ✕ Exit — close the sheet; end voice session; persist all completed turns; cut in-flight audio.
  • ⌨ Keyboard — exit to the dock with the latest partial transcript pre-loaded in the composer. Rescue path when voice is failing.

Transitions

  • entry → check mic + speech permissions → listening (or → permission-denied screen)
  • listening → VAD silence ≥ 1.4s + transcript non-empty → thinking
  • listening → tap 🔇 → paused
  • thinking → first tts_chunk → speaking
  • thinking → tts_error → error
  • speaking → tts_done → listening
  • speaking → tap orb → drain audio (~150ms) → listening
  • paused → tap 🎙 → listening
  • any → tap ✕ → close sheet; mic off; audio queue drained; voice session ended
  • any → tap ⌨ → exit to dock; latest partial transcript in composer
Why continuous-loop without barge-in
Barge-in (option 3 in the brainstorm) requires echo cancellation against a hot mic during TTS playback. AVAudioSession .voiceChat mode helps but doesn't fully solve it. We took the simpler shape now and reserved barge-in for M2.5 once we have dogfood data on what the conversation rhythm actually feels like.

5 Audio capture & VAD #

Mic setup, transcription, and how we decide a user turn is over.

Audio session

A new VoiceSession actor owns the audio session for the lifetime of the sheet.

// iOS — VoiceSession.swift (new)
let session = AVAudioSession.sharedInstance()
try session.setCategory(.playAndRecord,
    mode: .voiceChat,
    options: [.allowBluetooth, .allowBluetoothA2DP, .defaultToSpeaker])
try session.setActive(true)

let engine = AVAudioEngine()
let tap = engine.inputNode.installTap(onBus: 0,
    bufferSize: 1024,
    format: nil) { buffer, _ in
    speechRequest.append(buffer)
    vad.observe(buffer)
}

The .voiceChat mode gives us Apple's built-in echo + noise suppression for free. That matters because even without barge-in we want clean capture as the user starts a turn while speaker-audio echoes are decaying.

Transcription

SFSpeechRecognizer(locale: .current) with requiresOnDeviceRecognition = true for iOS 17+. Free, private, no quota.

  • Partials — used purely for the on-orb live transcript display. Throttled to ~5 fps so SwiftUI doesn't redraw the whole orb constantly.
  • Finals — committed on segment boundaries, but we don't send on result.isFinal. That fires when SFSpeech thinks the user is done, often prematurely. The VAD layer below decides.

VAD thresholds

ThresholdDefaultPurpose
silenceDuration1.4 scontinuous below-noise-floor input → commit utterance
minUtteranceMs350 msreject coughs / "uh" / accidental button taps
maxUtteranceMs30 sforce-commit even without silence (safety net)

Implementation: per installTap buffer we compute RMS power. If currentRMS < noiseFloor + 6 dB for silenceDuration, commit. Noise floor is a 2-second rolling average measured during the first entry → listening transition — adapts to a quiet bedroom vs. a busy café.

What gets sent

POST /channels/ios/inbound
Authorization: Bearer <deviceToken>

{
  "text": "summarise my email from finance",
  "conversationId": "ios:<deviceId>:<threadId>",
  "source": "voice",
  "voiceTurnId": "<UUID>"
}

The voiceTurnId lets the server's TTS sidecar tag outbound tts_chunk events so the client knows which utterance the audio corresponds to. Matters if the user rapidly fires two turns.

6 TTS pipeline #

From assistant tokens to audio in your AirPods, including the latency budget.

Server-side new components

  • server/voice/sentence-buffer.ts — pure function createSentenceBuffer({ onSentence }). Pushes deltas in, fires onSentence(text) callbacks. Splits on /(?<=[.!?:])\s/ with an allow-list exclude for Mr|Mrs|Ms|Dr|St|U\.S|e\.g|i\.e|\d+\.\d+. Unit-testable in isolation; zero external deps.
  • server/voice/tts-elevenlabs.ts — thin WS adapter. createElevenLabsStream({ voiceId, modelId, apiKey }) returns { send(text), end(), onChunk, onError, onDone }. ~100 lines. No shared state between turns.
  • server/voice/tts-sidecar.ts — orchestrator. Wires SentenceBuffer into the ElevenLabs adapter (or the local-fallback path), subscribes to broadcast() filtered by conversationId + voiceTurnId, emits tts_chunk / tts_done / tts_error / tts_use_local via broadcast(). Owns per-turn lifecycle.
  • server/voice/markdown-strip.ts — used only on the fallback path. Strips **bold**, backticks, # headings, bullets, fenced code blocks. The TTS-voice path doesn't strip because the agent verbosity hint already told the agent not to emit markdown.

iOS new components

  • ios/Boop/Voice/AudioQueue.swift — actor wrapping AVAudioEngine + AVAudioPlayerNode. Receives tts_chunk payloads, decodes audio/mpeg (ElevenLabs Flash v2.5 default), schedules into the player node. Transitions UI from thinking to speaking on first scheduled buffer playing (not first chunk received). On tap-orb-to-skip: stops the player, flushes queued buffers, resolves a drainPromise the state machine awaits before going listening.
  • ios/Boop/Networking/SSEClient.swift — adds the four new event types to the event-type enum and dispatch table. No new transport, no new connection.

SSE event vocabulary

EventPayload

Audio format & voice

ElevenLabs Flash v2.5 streams mp3_44100_128 by default — we accept as-is. AVAudioEngine decodes mp3 natively, no opus dep. ~16 KB/s = trivial over cellular.

Default voice ID: 9BWtsMINqrJLrRacOk9x (ElevenLabs "Aria"). Overridable via ELEVENLABS_VOICE_ID env. Per-thread voice selection is out of scope for M2.

Backpressure

If AudioQueue falls behind (queue depth > 8 chunks), the sidecar pauses reading from the ElevenLabs WS (sets WS to flow-controlled). ElevenLabs holds the connection open; resumes when iOS drains. Handles bad-cellular scenarios without dropping audio.

Latency-shaping note
With sentence-boundary chunking, the first sentence sets perceived latency. The agent verbosity addendum is critical: "Sure, here's a summary:" hits ~1.1s. A long preamble like "I'd be happy to help with that. Let me go through each one carefully:" hits the same first-audio at the comma, but informative audio is delayed 4–5s.

7 Server changes #

File-by-file deltas. Concrete enough to drive the implementation plan; abstract enough to survive code drift.

server/ios/router.ts — extend, don't rewrite
  • POST /inbound — accept optional source and voiceTurnId in the body; pass both into runTurn() via a new inbound.source field. Auth, pairing, rate limiting unchanged.
  • GET /stream — no transport change. The new tts_* event types pass through unchanged because they go via the existing broadcast() → subscribe() filter.
server/channels/index.ts — extend Inbound type

Add source: "sms" | "tg" | "ios" | "ios-voice". Default to "ios-voice" when source === "voice" and channel is iOS — this flows into the system-prompt switch.

server/interaction-agent.ts — voice-mode addendum

One change: where the system prompt is materialized, append the addendum when inbound.source === "ios-voice":

You are speaking to the user out loud through text-to-speech. Reply in conversational prose, not markdown. No bullet lists, no code blocks, no numbered sections, no asterisks. Lead with the answer in one sentence (≤ 12 words), then offer at most two more sentences of detail. If the user asks for a long list, summarise it in prose ("three things — first, …, second, …, third, …"). When you must read out code, URLs, or IDs, say "I'll send that as a text" and skip them aloud.

This addendum is conditional, not the default — text messages stay verbose as today.

server/voice/ — new folder, four files
  • sentence-buffer.ts — sentence splitter, regex-based with abbreviation allow-list. Pure function.
  • tts-elevenlabs.ts — ElevenLabs WS client. Single connection per turn. ~100 lines.
  • tts-sidecar.ts — orchestrator. Per-turn lifecycle. Created on first assistant_delta after a voice-source runTurn; destroyed on assistant_message.
  • markdown-strip.ts — fallback-path-only markdown cleaner.
.env.example — new vars 
# Optional. If unset, voice mode falls back to AVSpeech on iOS.
ELEVENLABS_API_KEY=
# Default voice — "Aria".
ELEVENLABS_VOICE_ID=9BWtsMINqrJLrRacOk9x
# Pinned by default; override only for evals.
ELEVENLABS_MODEL_ID=eleven_flash_v2_5

What doesn't change

  • Dispatcher, sub-agents, memory extraction, consolidation — untouched.
  • Convex schema — untouched. Voice turns persist via the existing messages.send mutation.
  • iMessage / Telegram paths — untouched. The verbosity hint is conditional on source === "ios-voice".
  • M1's pairing flow, bearer tokens, rate limits — untouched.

Failure modes (extending M1's F1–F10)

#FailureHandling
F11ElevenLabs WS fails to opensidecar emits tts_use_local immediately; iOS uses AVSpeech. Quality drop, no broken state.
F12ElevenLabs WS drops mid-turnsidecar emits tts_use_local with the remaining text. Mid-stream fallback. Awkward but no silence.
F13ElevenLabs 429 / quota exhausted1-minute negative cache, then tts_use_local. Next turn retries WS.
F14SentenceBuffer never flushes (long un-punctuated reply)1500ms safety timer force-flushes. Slightly worse prosody, never hangs.
F15Voice turn submitted while text turn already runningExisting per-conversation runTurn lock handles it. iOS sees no tts_* for the rejected turn, falls back after 5s thinking timeout.
F16User force-quits mid-speakingSSE drops → server cleans up sidecar via on('close'); WS closed. ~10 KB audio wasted.

8 Permissions & error handling #

First-launch flow, audio session edges, network edges, state-machine edges.

Permissions

Two distinct permissions, both required:

  • NSMicrophoneUsageDescription — "Boop needs your mic to hear what you ask in voice mode."
  • NSSpeechRecognitionUsageDescription — "Boop transcribes your voice on-device to talk to the agent."

First time the user taps the dock mic, a single permission card (not Apple's two back-to-back system prompts cold) explains both, then sequentially requests them. If either is denied, the card flips to a Settings → Boop → Microphone deep-link.

Audio session edges

EventHandling
Phone call arrives mid-listeningAVAudioSession.interruptionNotification → enter paused. On .ended + shouldResume, back to listening.
AirPods unplugged mid-speakingrouteChangeNotification with oldDeviceUnavailable → fade audio over 300ms, enter paused with "put AirPods back in".
AirPods plugged in mid-sessionroute change is silent; iOS routes audio to AirPods on next chunk. Brief pill: "Switched to AirPods".
Silent switch on.playAndRecord category bypasses silent; no special handling needed.
BackgroundedVoice mode pauses on scenePhase == .background; resumes on .active. Current sentence finishes via UIKit audio-background mode; mic detaches.

Network edges

#FailureHandling
V1SSE disconnects mid-listeningReconnect with backoff. Listening is local; nothing depends on the server.
V2SSE disconnects mid-speakingDrained chunks finish. On reconnect, replay with ?since=<last_seq>. Gap > 5 chunks → tts_error.
V3POST /inbound 5xxTransition to error with "Couldn't reach boop — tap to retry". Tap reuses the held transcript.
V4iOS sends utterance during server restart503 → V3 path.
V5SSE event arrives after tts_done for stale voiceTurnIdDispatcher checks current turn ID; stale events dropped.

State-machine edges

  • Sheet swiped down mid-speaking — same as ✕. Drain audio, end session, persist completed turns. Convex already has the assistant message via assistant_message.
  • Rapid mute-toggle — debounce 200 ms.
  • VAD never fires — maxUtteranceMs (30s) force-commits.
  • VAD fires on noise — minUtteranceMs (350ms) drops bursts. Empty transcript after a commit → don't POST, return to listening silently.
  • Idle hint — after 6s of listening with empty transcript, show a small "go ahead" hint.

Concurrency

  • Voice mode is per-app-instance — only one VoiceSession at a time, enforced by an iOS singleton.
  • Server-side, multiple voiceTurnIds from the same device are technically allowed; the continuous-loop UX serializes them in practice.
  • Multiple devices on the same boop instance — both can use voice mode simultaneously on different threads or even the same thread. Each device's sidecar streams to its own SSE.

11 Definition of done #

Concrete, measurable criteria for shipping M2.

  • Tap dock mic on the active thread → voice mode opens → ten consecutive turns work without exiting.
  • First-audio latency from VAD commit ≤ 1.5s p50 / ≤ 2.5s p90 on the ElevenLabs path. Measured via a voice_latency log line emitted server-side per turn.
  • All unit + UI tests green. Integration test green with mock ElevenLabs.
  • xcodebuild clean. npx tsc --noEmit no new errors beyond the 8 pre-existing ones.
  • iMessage path untouched — manual smoke send via Sendblue still works.
  • Text mode in the dock untouched — typing a message still POSTs without source and gets a verbose markdown reply (regression check).
  • ElevenLabs key absent → graceful AVSpeech fallback. Verified by unsetting the env var and re-running the integration test.
  • TestFlight build uploaded (CURRENT_PROJECT_VERSION bumped).
  • Boop IOS Design.md updated with an M2 status block.
  • This design doc and the implementation plan both live at docs/superpowers/{specs,plans}/2026-05-23-ios-voice-m2-*.html.

Worktree parallelization

  • Lane A — server: server/voice/*, server/interaction-agent.ts addendum, server/ios/router.ts extension.
  • Lane B — iOS: VoiceSession, AudioQueue, LottieView, VoiceModeSheet, permission card, SSE extension. Lane B uses a stub server emitting canned tts_chunk payloads until Lane A is ready.
  • Merge gate: integration test green on both branches before merge.

12 Scope & non-goals #

Explicit list of things deferred or out of scope.

  • Barge-in (mid-TTS interruption) — M2.5 candidate. Requires echo cancellation; deliberately deferred.
  • Voice-mode entry from Action Button / lock screen / Siri — M4 (App Intents).
  • Per-thread voice selection — M2.1. Default ENV var voice for now.
  • CarPlay integration — explicit non-goal.
  • Streaming TTS for outbound iMessage — voice mode is iOS-only; no SMS readback.
  • Background "always-listening" mode — explicit non-goal (battery, entitlements).
  • Voice for the share extension (M3) — share extension stays text-first.

13 Open questions #

Everything from the M1 design's open-questions list either remained open, was resolved, or shifted to M2's scope. None blocking implementation.

  • ElevenLabs cost during dogfood. Flash v2.5 is ~$0.10 per 1k characters on the Starter plan. A heavy week of dogfood (~100 minutes of TTS ≈ 100k chars) is ~$10. Acceptable for personal use. Document in ios/README.md.
  • VAD threshold tuning. 1.4s silence default is a starting guess. Expose a hidden Dev Settings panel with sliders so the maintainer can A/B during the dogfood week.
  • "Aria" voice — too generic? Possible follow-up: ship with a few curated voice presets in .env.example comments (Sarah, Brian, Bill, etc.).
